# Delta — 设计说明（一页）

## 三份互斥方案

1. **无限画布树**（QGraphicsView）。节点按树布局，拖拽、缩放、空间化分叉最直观。代价：读一段长链要在二维里移动，焦点、滚动、重启恢复都变复杂；它把「读」降级成「逛」。否决。
2. **三栏常规聊天**（侧栏 + 气泡 + 树状目录）。实现快、认知门槛低。代价：树只是右侧附录，分叉在正文里不可见；三栏挤压阅读宽度；整体像一个换皮聊天工具。实际做了 V1 后否决。
3. **单脊线 + 分支条 + ATLAS（采用）**。正文只画根→指针的一条链；分叉在链上留下可点击的窄条；右侧 ATLAS 给出整棵树的形状。代价：ATLAS 在几百节点会变密，分支预览只能截一行；换来连续的阅读和可解释的局部重排。

## 为什么选 3

- 赌**阅读**是主任务，不是浏览树。
- 赌分叉应该在场但不喧哗：一个可点击的分支条，比一张需要拖拽的画布更常被用。
- 赌「首选孩子」必须在界面上可见、可改（分支条右侧圆点），否则它只是数据库字段。
- 赌位置只是一个指针：可见链每次由父指针回溯，不落盘任何路径副本。

## 砍掉

- 画布、缩放、拖拽、自由摆放。
- 把整棵树塞进正文的缩进目录。
- 任何路径副本；以及「重排就是把整个列表清空重建」的实现。
- 流式期间做完整 markdown 排版：改为**追加式纯文本草稿**，完成时一次排版，换 token 上屏稳定在 2 帧内。
- 全列表 diff：改成以 node / fork id 为 key 的最长公共前缀 + 离屏卡片缓存。

## 推翻首版

V1 是「三栏气泡 + 右侧树目录」（spikes/v1_conventional.py，docs/screenshots/v1_conventional.png）。它最大的问题不是不好看，而是**分叉在正文里不存在**：你只能在右边的树里找，读完一条还要自己对齐；树成了附录，聊天成了主体。V1 也证明了「默认控件 + 临时布局」到不了标准。于是推倒，改成 spine / 分支条 / ATLAS。

## 热路径（对应验收）

- **链**：root → pointer 的父指针回溯；上下文只取这条链，兄弟分支永不出现在 prompt 里。
- **分支切换**：最长公共前缀的控件对象不动，只删/建后缀；回访复用缓存卡片（测试断言同一对象）。
- **流式**：daemon 线程只入队；主线程 14ms 批量取一次。流式期追加纯文本，完成时 markdown；中断时保留已收内容。
- **重启**：JSON 原子写 +（row key, offset）滚动锚点，而不是像素值。
- **首选**：只改一个节点的字段；不碰消息、指针和别的节点。

## 代价（不藏）

- 流式是「草稿 → 排版」两段式，完成时会有一次视觉落定。
- 超长回答（约 3k 字以上）完成时的一次性排版会出现 30–60ms 尖峰；token 阶段没有。
- ATLAS 没有搜索/缩放；分支预览只截一行；Markdown 是 Qt 富文本子集，无代码高亮。
